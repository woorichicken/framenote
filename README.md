# framenote

렌더된 영상에 **프레임 단위로 메모**를 남기고, 그 메모를 코딩 에이전트가 바로 받는다.

```bash
npx framenote out/final.mp4
```

브라우저 창이 하나 열린다. 영상을 보다가 화면을 끌면 그 자리의 **프레임 구간·좌표·렌더본**이
메모에 자동으로 붙는다. 사람이 채우는 칸은 "무엇이"와 "어떻게" 둘뿐이고, **"어떻게"는 비워도
된다** — "왜 이상한지 모르겠고 그냥 이상해"는 정당한 지적이고, 판단은 에이전트가 한다.

"에이전트에게 보내기"를 누르면 감시 중인 에이전트가 신호를 받아 소스를 고치고 다시 렌더한다.
**같은 창에서** 새 영상으로 바뀌고 보던 프레임은 그대로다.

## 왜

영상 피드백은 말로 하면 반드시 뭉뚱그려진다 — "저 부분이 좀 어색해". 한 지점을 가리키려면
**몇 번째 프레임 · 화면 어디 · 어느 렌더본**이 필요한데 말과 채팅으로는 그 셋이 실려 나가지
않는다. framenote 는 그 셋을 사람이 적지 않게 만든다.

## 프레임이 맞다는 것

이 도구의 존재 이유다. 브라우저의 재생 시각(`currentTime`)으로 프레임을 계산하면 키프레임
스냅과 반올림으로 1~2프레임 어긋나고 **에러가 안 나서 아무도 모른다.** 그래서:

- 프레임 레이트는 브라우저가 아니라 **영상 파일에서 직접** 읽는다(브라우저는 알려주지 않는다).
- 표시 중인 프레임은 브라우저가 **실제로 그린 프레임**에서 확정한다.
- 확정할 수 없는 브라우저에서는 **메모 작성을 잠근다.** 틀린 프레임이 붙은 메모를 만드는 것보다
  못 만드는 게 낫다.

프레임마다 번호를 태운 검증용 영상으로 이걸 스스로 확인한다 — `pnpm verify:frames` 는 요청한
프레임·플레이어가 보고한 프레임·화면에 그려진 숫자 셋이 같은지 본다.

## 에이전트가 붙는 곳

| 무엇 | 어디 |
| --- | --- |
| 붙을 주소 찾기 | `.framenote/server.json` (터미널 출력을 긁지 않는다) |
| 새 묶음 신호 | `ws://127.0.0.1:<port>/feed` — 묶음 식별자와 건수만 |
| 메모 전문 | `GET /api/notes?batch=<id>` 또는 `.framenote/<영상>/notes.jsonl` 직접 읽기 |
| 상태 바꾸기 | `POST /api/status` — **메모 단위 목록**. 반영됨에는 새 영상 경로를 함께 |

**파일이 원본이다.** 서버가 죽어도 메모가 남고, 에이전트가 파일만 읽어도 일할 수 있다.

## 지키는 것

- **밖으로 안 나간다** — 나가는 요청이 한 건도 없다. 서버는 `127.0.0.1` 에만 바인딩한다.
- **의존성 0** — WebSocket 서버까지 직접 구현했다. 시스템에 `ffmpeg`/`ffprobe` 는 필요하다.
- **이미지는 파일로** — 첨부는 파일로 저장하고 메모에는 경로만. 그림을 메모에 박으면
  에이전트가 한 번에 읽을 수 있는 양을 그림이 다 차지한다.
- **커밋·푸시·최종 렌더는 안 한다** — 되돌리기 어려운 건 사람이 누른다.

## 요구사항

Node 22 이상, `ffmpeg` 와 `ffprobe`.
