## 코드 위치까지 알려주기 (Player 모드)

**지금**: 메모에 담기는 건 프레임·좌표·이미지까지다. "이건 어느 파일 몇 번째 줄"은 없다.
에이전트가 화면에서 코드를 찾아가는 건 자기 몫이다.

**아이디어**: mp4 대신 `@remotion/player`로 컴포지션을 브라우저에서 렌더하면 DOM 이 생긴다.
클릭한 요소에서 소스 경로를 얻어 메모에 `source: "MotionScenes.tsx:142"` 를 싣는다.

**방법은 이미 갈렸다 (실측 2026-08-19)**
- Agentation 이 쓰는 React fiber `_debugSource` 방식은 **못 쓴다.** React 19 가 그 필드를
  삭제했고(facebook/react#28265) 대상 프로젝트가 React 19.2.3 이다. 그대로 가져오면
  **에러 없이 소스 경로만 조용히 빈다.**
- 되는 방법은 **빌드 시점 주입**이다. feedback-kit 의 `packages/build/src/source-attr.ts` 가
  JSX 여는 태그마다 `data-fk-source="파일:줄:칼럼"` 을 심는다. 의존성 0짜리 문자열 변환이라
  loader 로 감싸기 쉽다. Remotion 은 `Config.overrideRspackConfig`(rspack) 또는
  `Config.overrideWebpackConfig` 로 물린다.

**왜 지금 안 하나**
- **없어도 되는지 아직 모른다.** 씬이 7개뿐인 영상에서 프레임·좌표·이미지만으로 에이전트가
  코드를 못 찾은 적이 있는지 세어본 적이 없다. 세기 전에 만들면 안 쓰는 기능이 된다.
- **작업량이 2~3배다.** Player 렌더 · loader 설정 · 요소 → 좌표 역매핑이 붙는다.
- **Player 가 보여주는 건 최종 mp4 가 아니다.** 폰트 로딩 타이밍·`--gl=angle` 차이로 최종
  렌더와 미묘하게 달라서, mp4 모드를 대체하지 못하고 **표면이 하나 더 늘어난다.**

**착수 전 확인할 것**
1. 실제 메모 30건에서 "코드 위치를 몰라 에이전트가 되물었거나 헤맨" 비율
2. 3D 씬(`ThreeCanvas`)은 안이 WebGL 이라 어차피 요소를 못 잡는다 — 그 비중이 얼마인지
3. 주입한 속성이 **최종 렌더에는 안 들어가게** 번들을 나눌 수 있는지

## 문구를 바로 고치기

**지금**: 자막·화면 문구가 어색할 때도 다른 메모와 똑같이 "메모 → 에이전트가 고침 → 재렌더"
를 돈다. 오타 한 글자도 왕복이 한 번이다.

**아이디어**: 문구 트랙에서 문장을 인라인 편집하면 로컬 서버가 소스 한 줄을 patch 하고
재렌더한다. patch 대상은 **텍스트뿐**이다 — 좌표·타이밍·색은 되돌리기가 어렵고 다른 장면에
번지므로 자동 적용하지 않고 메모로 남긴다.

**왜 지금 안 하나**
- **문구 단일 원본이 없는 프로젝트가 있다.** e-fm-saechang-video 는 화면 문구가
  `src/scenes/Keyposes.tsx` 와 `src/motion/MotionScenes.tsx` **두 파일에 통째로 복사**돼 있다
  (문구 5개 전수 확인, 5/5 양쪽 존재). 어느 쪽을 patch 할지 정할 수 없고, 한 쪽만 고치면
  키포즈와 모션이 어긋난다.
- **비율을 모른다.** 메모 중 "문구만 바꾸면 되는" 게 몇 할인지 세고 나서 정한다.
- **되돌리기 경로가 없다.** 에이전트가 아니라 도구가 소스를 직접 고치는 첫 사례라, 잘못
  고쳤을 때 무엇으로 되돌리는지가 정해져야 켤 수 있다.

**착수 전 확인할 것**
1. 대상 프로젝트에 문구 단일 원본(`copy.ts` 등)이 있는가 — 없으면 그 추출이 먼저다
2. 실제 메모 30건 중 "문구만" 비율
3. patch 실패·오적용 시 되돌리는 방법 — 편집 전 원문을 어디에 남기는가
